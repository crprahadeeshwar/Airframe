# Airframe

Airframe is a flight tail logger built for aviation enthusiasts to record and manage aircraft flights.

It is primarily a **production-fundamentals project**: the goal is to learn how a real web application is structured, tested, secured, deployed, observed, and recovered—not to build a large feature set or as a SaaS.

## Tech Stack

- **Next.js** — application framework
- **React** — UI
- **TypeScript** — application language
- **Tailwind CSS** — styling
- **shadcn/ui** — UI components
- **Supabase** — authentication and PostgreSQL database
- **Vitest** — unit and integration testing
- **Playwright** — end-to-end testing
- **GitHub Actions** — CI
- **Vercel** — application deployment

## Architecture

At a high level, the Browser handles the UI and lets the user interact with and use the application. Next.js handles server-side operations and acts as a secure bridge between the frontend and the Supabase database- which is responsible for redundant auth checks, database operations, and custom functions. This database houses the user records.

The application also uses Supabase Row Level Security (RLS) to enforce user-level data access at the database layer.

Database schema changes are managed through versioned Supabase migrations.

For more details, see [`docs/architecture.md`](docs/architecture.md).

## Getting Started

### Prerequisites

- Node.js
- npm
- Supabase CLI
- Docker Desktop

### Install dependencies

```bash
npm install
```

### Environment variables

Create the appropriate local environment files and configure the Supabase connection values required by the application.

The required public variables are:

```text
NEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY
```

Testing also requires the local Supabase environment generated by the Supabase CLI.

### Start the development server

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Local Database

Airframe uses Supabase locally for development and integration testing.

Start the local Supabase stack:

```bash
npx supabase start
```

Reset the local database and apply all migrations:

```bash
npx supabase db reset
```

Generate updated TypeScript database types when the schema changes:

```bash
npx supabase gen types typescript --local > src/lib/supabase/database.types.ts
```

## Testing

Airframe has multiple layers of automated verification.

### Unit and integration tests

```bash
npm test -- --mode test --run
```

The test suite covers application logic, validation, authentication, database interactions, authorization, and other application behavior.

### End-to-end tests

```bash
npx playwright test
```

The E2E suite verifies critical user workflows against the deployed application environment.

### Linting

```bash
npm run lint
```

### Type checking

```bash
npm run typecheck
```

### Production build

```bash
npm run build
```

The full CI pipeline runs these checks automatically before changes are merged.

## CI/CD

The repository uses GitHub Actions to verify changes before they reach `main`.

Vercel automatically deploys the application after changes are merged.

See [`docs/deployment.md`](docs/deployment.md) for the deployment process and environment configuration.

## Observability

Airframe includes a small application-level logging layer using structured JSON logs.

Important events include:

- Authentication successes and failures
- Flight creation, updates, and deletion
- Flight read failures
- Statistics failures
- Database health failures

A database-backed health endpoint is available at:

```text
/api/health
```

The endpoint verifies that the application can successfully communicate with the database.

## Security

Security considerations include:

- Input validation
- Authentication/session handling

- Secrets kept outside the repository

See [`docs/security.md`](docs/security.md) for the security review.

## Backup and Recovery

The database schema is reproducible through Supabase migrations.

Manual database dumps are also supported:

```bash
npx supabase db dump -f airframe-backup.sql

```

Daily database backups are automated through GitHub Actions and stored in a private Cloudflare R2 bucket.

Backups are stored as both the latest snapshot and dated daily snapshots.

A full restore drill and recovery procedure are still being finalized. See docs/recovery.md⁠￼ for the recovery documentation.

## Project Status

Airframe is currently a **pre-production project**.

The core application, authentication, database security, automated testing, CI/CD, deployment, observability, and documentation have been implemented and validated.

The remaining operational work is the backup/recovery drill and durable off-site backup process.

The project is intentionally kept small so that the focus remains on understanding production software fundamentals rather than accumulating features and commercialisation.
